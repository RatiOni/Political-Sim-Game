# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-player political/state-management simulation game in pure Python. Two front-ends share one simulation engine:

> **Current scope: Ardenia-only, by design.** A new campaign always plays **Ardenia**. The wizard presents one selected "Begin the Ardenia campaign" choice and explains that neighbouring states remain active world actors. The other eight countries are fully implemented as *data and as world actors* — AI governments with agendas and plans, diplomacy targets, map neighbours, civil-war candidates — and everything in `engine/` is country-agnostic (see "Country-neutral content"), but they are **not player-selectable yet**. The gate is one constant — `ui/menu.py: PLAYABLE_COUNTRY_IDS` — plus a guard in `CountrySelectStep.collect`; widening scope later means adding ids to that set, not unpicking anything. Do **not** remove the other eight from content, worldsim, or the map; `build_state_for(<any id>)` must keep working, and tests still exercise it.

- **`gui.py`** — the real game: a PySide6 (Qt6) desktop app with a main menu, New Campaign wizard (country → character → difficulty → seed), world map, and save/load.
- **`main.py`** — a terminal front-end that always starts the fixed Ardenia scenario. Fast iteration target; it's what `smoke_test.py` drives.

No build system, linter, or dependency manifest — a plain source tree run against the interpreter in `.venv` (PySide6 is the only third-party dependency).

## Commands

- **Run the GUI:** `.venv\Scripts\python.exe gui.py`
- **Run the CLI:** `.venv\Scripts\python.exe main.py`
- **Run the engine/CLI test suite:** `.venv\Scripts\python.exe smoke_test.py`
  Not pytest — one hand-rolled script, `assert`-based, `PASS`/`FAIL` per check, exit 1 on failure. Sections run top-to-bottom in one process: **A** direct mechanics, **B** action-menu integration (scripted numeric input), **C** turn-loop invariants, **D** modifier lifecycle, **E** stability, **F** elections + turnout, **G** campaign framework/persistence (including G5b–G5i opposition play), **H** dynamic events, **I** living world + civil war, **J** organic inflation, **K** intraparty currents, **L** flavor layer + event chains, **M** roleplay (identity gating, leadership moves, the rival), **N** immersion (press, structured news, world arcs), **O** consequential wings (rebellions, leadership, cohesion), **P** diplomacy verbs (pacts, sanctions, summits, treaty exit), **Q** pacing (world deliberation + PC upkeep), **R** cabinet personalities (traits, shortlists, representation), **S** regression guards (bugs found in review), **T** country-neutral content (roles resolve in all nine countries), **U** dramatization (schemer arc branching, rival escalation, dispatch variety), **V** Ardenian canon (capital, lore coherence, campaign opening), **W** the Vasca arc, **X** lore-package compatibility and integrity, **Y** the Vetrenka arc, **Z** the daily clock + opposition legislation, and **AA** canonical Ardenian blocs. Note the sections do **not** appear in alphabetical order in the file (X is immediately after W; V/T6 and then Z follow, with Y and AA last) — find one by `grep -n '^section("Y'`, not by scrolling. No way to run one section in isolation — comment others out or write a throwaway script.
  Sections **AB**, **AC**, **AD**, **AE** and **AF**, appended after AA, cover the Ardenian regional simulation, annual appropriations, ministry delivery, the household economy, and reform objectives respectively.
  **Seeded-stream fragility:** tests that `random.seed(...)` then assert a specific trajectory WILL break when new content adds RNG draws (each event/name-gen consumes stream). Write such tests against direct mechanics (no turn loop), or patch `engine.events.event_catalog` — see I5/H/L for the idiom.
- **Headless GUI test:** `.venv\Scripts\python.exe ui_smoke_test.py` — **known pre-existing issue:** any check that calls `.exec()` on a modal dialog hangs forever under `QT_QPA_PLATFORM=offscreen` on this machine (nothing clicks it), and the script only prints its results at the end, so a hang looks like zero output. Don't treat a hang as a regression. The working idiom is to patch the modals out and run the file's `main()`:
  `QDialog.exec = lambda self, *a, **k: 0` (plus `QMessageBox.exec`/`.information`) before `import ui_smoke_test; ui_smoke_test.main()`. The six system pages are no longer modal (they live in the desk overlay), so they test directly.
- **The visual target** is `docs/ardenia_ui_mockup.html` — open it in a browser before changing dashboard layout.
- Offscreen rendering has no fonts → text draws as boxes in screenshots. Register a TTF via `QFontDatabase.addApplicationFont(r"C:\Windows\Fonts\arialbd.ttf")` in the harness when a readable render matters.

## Architecture

### Layering: `models/` → `content/` → `engine/` → (`main.py` / `ui/`)

- **`models/*.py`** — plain dataclasses only. Nothing here imports `game_state.py` or `engine/*` (no circular-import risk when adding `GameState` fields that reference model types).
- **`content/*.py`** — data: `countries/*.json` (nine countries; adding one is a JSON file + a map cell), `bills.py`, `budget.py`, `households.py`, `reforms.py`, `events.py`, `traits.py`, `campaign_content.py`, `regions.py`, `lore/`, and `loader.py` (`build_state_for(id)` assembles a full `GameState`; it also wires bilateral relations for **every** country pair and seeds authored `meta.stability_value` + civil-war risk).
- **`engine/*.py`** — all simulation logic. `turn.py: TurnEngine.advance()` is the per-month loop; its docstring lists the exact phase order (order matters — later phases read earlier phases' same-turn results). Key modules: `legislative.py` (incl. `apply_effect_bundle`, the shared consequence pipeline), `budget.py` (annual structural appropriations), `ministries.py` (capacity/workload/delivery/backlog), `households.py` (regional living standards and confidence), `reforms.py` (live diagnoses and reform-design state), `regions.py`, `elections.py` (deterministic turnout → seats), `stability.py` (shared signal functions), `worldsim.py` (AI countries acting on agendas), `crisis.py` (civil-war gauge), `events.py`, `campaign.py`, `persistence.py`, `player_ops.py`, `actions.py`.
- **`game_state.py`** — the one `GameState` dataclass everything reads/mutates. No other module-level mutable game state exists.

### The GUI shell

`ui/app.py: MainWindow` is a dashboard — header (country · who · date, **plus the Play button and the 1–5 speed pips**) → nav bar → `AlertStrip` → left stats / map / right panel → assembly strip → full-width dispatch feed — plus the **political desk**, a single-page overlay (`ui/dock.py: SystemDock`) holding the six system pages.

**One navigation system.** The nav bar owns all six destinations; the menu bar carries only `Game`. Clicking a nav entry opens the desk on that page, clicking the same entry again closes it, as do Escape, the header's back arrow and a scrim click. The desk went through two earlier shapes and the current one is a reaction to both: as modal dialogs the pages froze the dashboard, and as a tabbed `QDockWidget` they *competed* with the menu bar for the same six destinations (with tab labels eliding to "Polic… Cabi… Part…") and, being part of the layout, **compressed** the dashboard when opened. So the desk is now a frameless child widget positioned over the central widget at a fixed 428px (min 380), animated in from the right over a scrim — **opening or closing it must never reflow a column behind it.** `SystemDock` kept its class name and public surface (`TABS`, `refresh`, `select_tab`, `current_page_name`, `has_uncommitted_input`, `set_selected_country`, `visibility_changed`, `uncommitted_changed`) so callers did not have to be rewritten around a container change. `MainWindow.resizeEvent` must keep calling `_dock.reposition()`; a resize mid-slide abandons the animation and snaps, because otherwise the animation lands on an x computed from the old window width.

The pages are plain widgets (`widgets_common.PagePanel`, aliased as `PageDialog`) that live for the whole session. Consequences to respect: the desk pushes the live `GameState` into every page on each `_refresh_all` (pages can't assume the state object they were built with is current — loading a save replaces it); only the visible page is redrawn, hidden ones are marked stale and catch up when shown; `PagePanel` deliberately renders **no title of its own** (the desk header names the page — it used to print the word twice); and because modality no longer blocks input, the clock is guarded explicitly by `PagePanel.has_uncommitted_input()` (only CabinetPage's drawn-but-unappointed shortlist returns True) plus a re-entrancy flag in `advance_turn`. `EventDialog`, `TurnSummaryDialog`, and the breakdown dialogs remain deliberately modal.

**Dashboard conventions worth not undoing.** A progress bar is only for a bounded 0..1 value where higher is better — growth, inflation and debt/GDP therefore get figures and a trend glyph, never bars (`panel_left.py`, whose trend comparison snapshots per *turn*, not per repaint). `AlertStrip` is a queue of clickable routes; when nothing is pending it shows **nothing at all** — no "no pressing alerts" sentence. The seat arc (`widgets_assembly.py`) lives on the Parties page, not the dashboard, which carries a one-line strip linking to it.

**Nothing on the dashboard may change size when the state changes.** This is the fix for a reported "the UI keeps moving/resizing itself" bug, and every part of it is load-bearing:
- `AlertStrip` reserves a **constant band** whether or not it has cards. It originally collapsed to zero when empty, and that collapse *was* the bug — every situation that fired or resolved shoved the whole dashboard down and back up. It also overrides `minimumSizeHint()` to a small width, because a widget reports its layout's total minimum as its own and a row of fixed-size cards would otherwise widen the window as alerts arrived.
- `_NeedCard` is fixed width **and** fixed height; cards clip rather than wrap.
- `EventLog` is a fixed-height block of fixed-height `_DispatchLine`s (2 text rows each). Unused rows are blanked, **not hidden**, so a quiet turn and a busy one occupy identical space.
- The general rule behind all of it: a wrapping or variable-length label sizes itself to its content and propagates that up to the window. Anything on the dashboard whose text changes per turn needs an explicit fixed size or an `ElidedLabel`.

**Desk pages must fit the desk, never scroll sideways.** `ScrollColumn` sets `ScrollBarAlwaysOff` horizontally, and `KeyValueRow`'s key is an `ElidedLabel` (the value keeps its full width — a clipped figure is worse than a clipped label). Two plain QLabels summing their text widths is what pushed the Policies budget list past the 428px desk and grew a horizontal scrollbar.

### Two front-ends, one action implementation

Every player action's real logic is one input-free `op_*(state, ...) -> ActionResult` in **`engine/player_ops.py`**. The CLI (`engine/actions.py`) gathers input via `choose()`/`input()`; the GUI (`ui/pages.py`, `ui/dialogs.py`) gathers it via widgets and calls the same op through `MainWindow._run_op`. **New action logic goes in `player_ops.py`** — never duplicated into both front-ends.

### Opposition play

The campaign wizard's character step chooses both `party_id` and `opening_role` (`contextual`, `government`, or `opposition`). Campaign generation assembles a compatible governing coalition and stamps `Player.in_government` / `ruling_faction_id`; choosing a party outside power is a complete campaign path, not presentation flavour. Government-only operations remain gated while the player is outside office, and winning an election restores the country's authored government title.

`engine/domestic_ai.py` runs the non-player government's legislative programme while the player opposes: it diagnoses, introduces a bill from the shared catalogue, leaves a response window, and resolves the vote through the same `engine/legislative.py` pipeline as player legislation. The player may support, oppose, or amend that bill once through shared `player_ops` calls; the sponsor, response and timetable live in `GameState.domestic_politics`. Outgoing government bills lapse when power changes.

`engine/opposition.py` is the government-in-waiting layer: up to three manifesto pledges, credibility, issue campaigning with cooldowns, and a named `shadow_cabinet`. Shadow ministers retain ordinary competence and personality data, shape pledge campaigning, and are promoted into the real cabinet after an election victory; delivered and broken promises feed the next electoral verdict. The GUI exposes this through the opposition versions of the Policies and Cabinet pages, and the CLI has the matching Opposition action category. Sections G5b–G5i are the regression guardrail for party/opening-role coherence, AI legislation, parliamentary responses, a full opposition term, pledges, shadow appointments, persistence and transition into office.

### The Modifier system

`models/modifiers.py: Modifier` is the mechanism for *any* delayed/lingering effect (laws, loans, treaties, events): `onset_delay → ramp → hold → decay`. The engine recomputes each modifier's current value fresh every turn — nothing accumulates — so effects stay bounded forever. **Attach a Modifier rather than repeatedly mutating a stat.** `institutional=False` is reserved for contractual effects (loan interest) that no minister or crisis can discount.

### Determinism philosophy

Elections, turnout, stability, civil-war risk are **never rolled** — they're deterministic functions of tracked state. RNG appears only in event/scandal/protest/agenda *triggers* (seedable in tests via `random.seed`).

### The voice layer

Dispatches route through `engine/flavor.py: say(state, key, **fields)`, which picks a wording variant from the template pools in `content/dispatches.py`. Variant choice uses a **local** `Random` seeded from (turn, key, log-position) — never the global RNG stream (that would shift every seeded test). `MARKERS` in dispatches.py guarantees a stable keyword per dispatch type; tests match on markers, not exact wording. Named people feed the templates: `Faction.leader` (authored in ardenia.json, generated elsewhere via `cabinet_ops.generate_name()`) and `Country.leader_name` (from each JSON's `default_player`).

### Consequential wings

A bill with an authored `Law.ideology` splits every multi-wing party's seats across its wings (`legislative.wing_votes`, largest-remainder): each wing votes the party line ± its own read of the bill (`WING_SALIENCE`), so distant restless wings rebel (`vote_rebellions`, dispatched on resolve). A bill with `ideology=None` keeps the exact legacy bloc vote — that's the safety gate. Wing takeovers by a disloyal wing (loyalty < 0.5) oust non-player party leaders (`parties.update_party_wings`); the player's own party instead raises the `party_leadership_challenge` situation (options use `EventOption.on_apply`, the content-callback hook for effects a LawEffect can't express). Average coalition cohesion feeds `compute_target_stability` ("Coalition cohesion" component, zero drag at full cohesion).

### The press layer

`flavor.say` records every dispatch as a structured `(key, fields, text)` item in `GameState.turn_news` (ephemeral, cleared per turn); the few direct `state.log` dramas (situations, elections, confidence votes) append their own captures. `engine/press.py: front_page(state, before, after)` ranks them by drama and builds a newspaper (masthead from `Country.paper`, else "The X Herald") from the headline/lead pools in `content/press.py` — `SAMPLE_FIELDS` there documents each key's fields and is linted by Section N. The GUI's `TurnSummaryDialog` IS the front page; the CLI prints the lead above the turn log. `GameState.world_arcs` (persisted) tracks named one-time world developments (axes/feuds) detected in `worldsim._update_world_arcs`.

### Roleplay layer

The player's identity is mechanical all game: each `Background` in `content/campaign_content.py` carries an ongoing ability (`action_label`/`action_deed`/cost/cooldown) executed by `player_ops.op_background_action`; `op_address_nation(state, tone)` gives four context-dependent tones. Both live in the CLI "Leadership" category and on the GUI Briefing page. Cooldowns are generic: `GameState.cooldowns` + `player_ops.on_cooldown/start_cooldown`. `EventOption.requires` (a callable on state) gates situation options by background/ideology — enforced in `events.available_options`, `op_resolve_event`, the CLI listing, and `EventDialog`; an event's default option must never be gated (auto-lapse takes it; Section M lints this). `engine/roleplay.py` supplies the dynamic rival (strongest hostile party's leader) who jibes after stumbles, escalating across a campaign: `jibe_tier()` picks between the `rival_jibe` / `rival_jibe_sharp` / `rival_jibe_bitter` pools from a counter kept in `GameState.cooldowns` (already persisted, so no new field) plus current approval — dismissive early, sharper once blows land or the government struggles, bitter for a rival who keeps being right and losing anyway.

### Ardenia's history (canon)

`content/lore/` is the single pure-data source of truth for Ardenia. `__init__.py` preserves the legacy public API (`OVERVIEW`, `TIMELINE`, `PARTY_ORIGINS`, `FIGURES`, `opening_briefing()` and the standing constants); `timeline.py` holds the pre-1918 floor plus the unchanged eleven-entry modern timeline; `geography.py` holds regions, cities, the Kesla and ceasefire line; `society.py` holds peoples, language/script, faith and social order; `institutions.py` holds the constitutional settlement, officeholders, armed structures, Directorate files, law, media and civil society; `economy.py` holds the transition economy, sectors, kron, energy and foreign obligations; `parties.py` holds origins plus canonical blocs and their small simulation profiles; and `figures.py` holds everyone whose authority or memory remains live. Every authored item has a stable id and uses only builtin containers. Nothing under the package may import from `engine/` or `models/`, and the numeric facts in its prose are flavour rather than simulation inputs.

The GUI Codex (`ui/pages.py: HistoryPage`) and the CLI `history` command render that same package; `engine/campaign.py: _opening_briefing` continues to seed the first three campaign dispatches through the compatibility export. **Krasova is the Kolvenian Union's core successor state and Vetrenka's backer** — that is why it is Ardenia's default antagonist. The player's default name deliberately matches the Liberal Democrats' leader: the player *is* the party leader, elected at the Reckoning. That is not a bug; do not "fix" it. Vasca's fate and Vetrenka's future are now played out in content (see "Bespoke Ardenian arcs"); what became of Doncic and Yeska remains deliberately open.

### Canonical Ardenian blocs

Ardenia does **not** use the generic `Moderates/Mainstream/Hardliners` spectrum. `content/lore/parties.py:BLOCS` and `BLOC_PROFILES` define its twelve social currents — the Circle, Return, Capital Bar, Square, Line, Parish, Works, Reform Wing, Grange, Left-Out, Shop Floor and Nostalgics. `content/loader.py` turns those records into the live `Faction.wings` with `kind="bloc"`; other countries still use authored or generated generic wings. A bloc owns a party-seat share, ideology, leadership loyalty and small bill-specific interests. `engine/legislative.wing_votes` includes those interests, and a named rebellion reduces that bloc's loyalty, feeding the existing cohesion/stability system. `PartiesPage` shows the live balance, social base and strongest current policy pulls. `engine/persistence` round-trips all fields and upgrades only the exact known pre-canon Ardenian spectra, leaving unfamiliar/modded party data alone.

### Country-neutral content (roles)

`content/events.py` names no country's parties or neighbours. Faction effects address canonical **roles** — `models/roles.py`: `@labour`, `@business`, `@nationalist`, `@agrarian`, `@reform`, `@establishment`, whose centroids are the cluster means of the 37 authored factions across all nine countries. `content/loader.py` stamps `Faction.role` (nearest centroid) at build time; `legislative.resolve_faction_key` turns a role into a concrete faction when the effect lands — the single resolution point, because the mapping is per-country. `role_faction` picks whoever is **furthest out on the role's defining axis** (`ROLE_AXIS`), so Ardenia's labour bloc stays the Workers' Front and Terand's nationalists are the Military Bloc; if no faction classifies into a role, it falls back to the best sign-correct candidate (Solheim's Liberal Party covers business). Diplomatic effects use `TARGET_COOLEST` / `TARGET_MOST_HOSTILE`, resolved against the relation that triggered the event (`events.resolve_relation_target`).

Section T is the guardrail: it asserts every role resolves in every country apart from an explicit, re-verified exception list (only Terand/labour — no faction there sits left of centre), that every option's declared roles land sign-correctly in all nine countries, and that no option is a silent no-op anywhere. **A new country JSON or an edited ideology vector will fail Section T if it creates a role gap** — that's the point.

### The schemer arc (a branching chain)

The one multi-step, *branching* story: `a_schemer_stirs` → (`confront` → `a_schemer_confronted` | `wait` → `a_schemer_moves`) → `a_schemer_triumphant` → hands off to `party_leadership_challenge`. Entry is gated on the schemer trait's own threat curve, so it plays in whichever country's cabinet has a schemer — never a hardcoded minister id. Every step re-resolves its subject via `_arc_schemer(state)` and no-ops quietly if that minister has since left. **Note:** `threat_level()` is `ambition × (1 − loyalty)`, so schemers carry `loyalty_drift` in `TRAIT_EFFECTS` — without it a minister appointed at loyalty 0.5 was capped at 0.475 threat and neither this arc nor the older `minister_restless` warning could ever fire. Section U0 pins that.

### Bespoke Ardenian arcs (Vasca, Vetrenka)

Two of Ardenia's open historical wounds are played out as event chains in `content/events.py`. Unlike everything else in that file they name **literal faction ids and one literal country id** rather than roles/sentinels — they are specific stories about specific parties, not reusable content. The price of that licence is `ARDENIA_ONLY_EVENTS`: every id in it must be provably unable to fire elsewhere, which **Section T4b enforces** (it also validates that the literal ids actually exist, and still forbids literal ids in every non-bespoke event).

- **The Vasca question** — `vasca_stirs` → crackdown / amnesty / downplay, converging on `vasca_last_stand`, whose three endings include "no ending". Outcomes are decided by `_security_effectiveness(state)`, not a fixed roll. Section W.
- **Vetrenka (the frozen conflict)** — deliberately a different *rhythm*: a recurring `vetrenka_friction` (cooldown 6, four incident flavours, resolves nothing, counts itself into `campaign_meta["vetrenka_incidents"]`), and only after `FRICTION_BEFORE_CROSSROADS` of them the once-only `vetrenka_crossroads` opens with three roads — peace process / offensive / quiet partition — each two more steps deep and each ending two ways, for six distinct terminal states in `campaign_meta["vetrenka_status"]`. `formalise` is the **default** option, so a government that never engages lets the line harden by inattention. Section Y.

Both feed `GameState.insurgency_pressure` (see `engine/crisis.py`), and both lock permanently once resolved — status set ⇒ neither layer can reopen.

**Odds curves in this content read *deviation from the ordinary case*, not raw stats.** A real Ardenian government reaches the crossroads with approval 0.47–0.50 and stability 0.41–0.51 — so a curve like `0.25 + approval*0.45` is effectively a constant in play. Section Y8 pins that the same roll splits governments differing by as little as 0.11 approval; if you retune these, keep that test meaningful.

### Dynamic events (chains)

`content/events.py` holds 20+ situations. `EventDef.once`/`cooldown` gate repeat fires (tracked in `GameState.event_fire_history`); an `EventOption.follow_up` (`{event_id, delay, chance}`) schedules a delayed consequence into `GameState.scheduled_events` — chain-only events use `condition=_never, chance=0.0` and fire exclusively via follow-ups, which bypass condition/cooldown gating.

### Cabinet personalities

`Minister.trait` + `TRAIT_EFFECTS` (in models/cabinet.py — mechanics can't live in content/ because models may not import upward): technocrat/firebrand/loyalist/grandee/schemer, each with real hooks — `effective_competence()` (feeds `implementation_quality`), `threat_level()` multipliers, an appointment loyalty bonus, a drift-proof loyalty floor, a capped cabinet `stability_trait_bonus`, and per-turn schemer growth (`turn.py:_update_ministers`, which also fires the `minister_restless` warning on threat > 0.5 with a per-portfolio cooldown). Appointment = choosing from `cabinet_ops.shortlist` (own party / coalition partner / high-competence wildcard) via `op_appoint_minister`; coalition partners drift +/− loyalty by cabinet representation (`_update_faction_loyalty`). The old `reshuffle(faction_id)` path still exists for compatibility.

### Diplomacy verbs

Beyond improve/trade/loan/condemn, the player holds real statecraft (`engine/diplomacy.py` mechanics + `player_ops.op_defense_pact/op_impose_sanctions/op_lift_sanctions/op_hold_summit/op_break_treaty`): defense pacts (trust-gated ≥0.45, both-sides `Treaty(type="defense")`, and `worldsim._hostile_action` shelves 50% of hostile moves against a pact-holder), sanctions (`BilateralRelation.sanctioned`, mirrored + persisted; the target bleeds growth/stability monthly in `simulate_world`, the player eats a lost-markets modifier if trade was big), summits (cooldown "summit"), and treaty exit (both-sides removal, penalty scaled by treaty type, a trade pact's growth modifier dies by `source_id`). Treaties age via `turns_active`.

### The world is alive

`engine/worldsim.py` runs every non-player country each turn: economy/stability drift, world↔world relation drift, and a **deliberation loop** (`_pursue_agendas` → `_make_plan`/`_execute_plan`): each country evaluates its national interest (`_national_interest`, deterministic — agenda type from `Country.agenda`: hegemon/revanchist/trader/reformer/survivor/ideologue + optional rival/ally; a sanctioning power outranks everything), commits to a `Country.plan` (persisted), foreshadows hostile/trade plans via the `world_deliberates` dispatch, executes when the plan matures (staggered openings — months 1–2 are quiet; then one action per country every ~3–5 turns), and plans again — including acting on the player. `engine/crisis.py` tracks a 0..1 civil-war gauge for player and world countries; past `CIVIL_WAR_RISK_THRESHOLD` it latches an ongoing catastrophe (recurring penalties, not a game over). Valmora is the authored crisis start (~0.72 risk).

### Annual appropriations

`models/budget.py:AnnualBudget` records one fiscal year's structural spending settlement: eight stable envelopes from `content/budget.py`, a revenue forecast, source/status, lobbying and the parliamentary division. `GameState.active_budget` owns the current year, `pending_budget` holds a proposed or approved successor until 1 January, and `budget_history` preserves resolved plans. `engine/budget.py` seeds fresh campaigns and old saves from `Economy.structural_expenditure`, validates percentage reallocations, translates their overall size and composition into the shared legislative ideology/vote machinery, and changes the structural expenditure baseline only when the plan takes effect. Laws, treaties, loans, regional programmes and emergencies remain modifiers or headline additions on top; they are not hidden inside the appropriation envelopes. The original seven-envelope format migrates by carving Foreign Affairs out of State Administration while preserving the voted total.

Government players draft, lobby, vote and revise through input-free operations in `engine/player_ops.py`; both the Policies page and the CLI's appended `Budget` category use those calls. Failure to pass a plan by January creates a three-percent continuing-budget reduction plus a modest political penalty. When the player is in opposition, `engine/budget.py` enacts a restrained plan authored from the actual ruling party's ideology and does not punish the player as though they controlled the treasury. Section AC guards construction, timing, voting, continuation, persistence, opposition ownership and CLI parity.

### Ministry capacity and delivery

`GameState.ministries` holds one persistent `models/ministry.py:MinistryState` for every `CORE_PORTFOLIO`: baseline/current funding, funding ratio, workload and its breakdown, operating capacity, delivery, backlog and consecutive overloaded months. `engine/ministries.py` recalculates these before economic policy effects each month. Capacity combines the portfolio's enacted appropriations, the responsible minister's competence and loyalty, national bureaucratic capacity and government stability. Workload comes from ordinary administration plus the systems the player actually creates or inherits: active laws, regional programmes, unresolved portfolio situations, treaties, sanctions, loans, regional pressure and civil war. Unserved work becomes a bounded backlog; only spare capacity clears it, so appointing one good minister does not wipe away years of institutional debt overnight.

Ministry delivery moderately multiplies the existing portfolio implementation path rather than replacing it: `TurnEngine._implementation_quality_for` still accounts for the minister, stability, bureaucracy and cabinet risk, then applies the department's ability to carry its current load. `engine/regions.program_delivery_quality` uses the same departmental constraint. This means an overcommitted Economy ministry weakens both national reforms and local industrial programmes, while contractual effects such as loan interest remain institution-independent. The Cabinet page and the CLI's appended `Inspect Ministry Delivery` action read the same ledger. Section AD guards workload sources, budget/leadership trade-offs, backlog accumulation/recovery, real policy and regional consequences, persistence, migration and front-end parity.

### The household economy

`GameState.households` persists 36 `models/household.py:HouseholdGroupState` records: six social groups in each of Ardenia's six regions. Group definitions and regional population shares live in `content/households.py`; numbers there describe exposure to growth, jobs, prices, public services and welfare rather than party loyalty. `engine/households.py` updates nominal income, living costs, real income, employment security, service access, hardship and confidence on each monthly pulse, after regional conditions are updated and before approval and stability. The national figures are population-weighted aggregates of those regional lives, not a second set of headline economy fields.

Inflation and growth affect groups unevenly; local unemployment determines job security; state reach determines how much public provision arrives; and welfare/education appropriations are filtered through Finance's payment machinery and Interior's territorial administration. Household confidence rewards the player when governing and creates political opportunity when the player is in opposition. Regional confidence shifts the sitting party's local support, while severe national hardship adds a bounded component to unrest. The Briefing page and CLI dashboard expose the shared aggregates and hardest-hit groups. Countries without authored household distributions keep an empty ledger and retain their previous behavior. Section AE guards distribution, unequal shocks, regional labour markets, the funding/delivery interaction, political ownership, persistence, migration and long-run bounds.

### Reform design

Reforms now begin with a persistent **objective**, not a pre-written bill. `content/reforms.py` defines seven stable purposes and the live signals relevant to each: purchasing power, work and wages, public services, productive modernisation, fiscal room, state capacity, and regional/land inequality. `engine/reforms.py` normalizes current economic, household, regional, budget and ministry conditions into explainable 0..1 pressures, ranks the objectives, and records the chosen objective as `GameState.reform_project` (`models/reform.py:ReformProject`). The project freezes its diagnosis-at-adoption while the live diagnosis continues to move, preserving why a government began a reform and allowing the player to judge whether conditions improved.

`player_ops.op_adopt_reform_objective` is available in government and opposition: choosing a purpose does not itself change the country, and opposition adoption is explicitly a programme rather than an exercise of executive power. The Policies page and the CLI's appended `Reform Design` category use the same ranking and operation. Replacing direction is possible at a smaller political-capital cost; adopting the already-active objective is a no-op. Persistence round-trips the project, while old saves receive no invented objective. Countries without authored household data use restrained national proxies rather than false zero-access assumptions. **Only the objective stage exists so far**: instrument, scope, concessions, bill construction and implementation review are subsequent slices. Section AF guards signal integrity, shock sensitivity, political ownership, persistence, both front ends and country neutrality.

### The PC economy

`turn.py: political_upkeep(state)` — every active law (0.8), treaty (0.6), and sanctions regime (1.0) consumes a slice of the monthly PC gain ("governing overhead"), floored at `PC_REGEN_FLOOR` (3.0) so no government is paralysed. Shared by the turn engine, the CLI capital bar, and the Briefing page's "Governing overhead" row. Repealing laws / exiting treaties frees capacity — the brake scales with commitments, not with time.

### Organic inflation

`turn.py: _update_structural_inflation` — deficits push structural inflation up, growth above trend overheats it, an anchor pulls it toward ~2%. Policy modifiers layer on top of the organic base.

### One colour system per job

The base palette is **burgundy**, not the original navy: `BG`/`PANEL_BG`/`PANEL_RAISED` are a warm wine-red ramp with a gold `ACCENT`. If you darken them, darken them together or the surface hierarchy stops being legible. Two things were retuned *because* of that switch and should not be reverted piecemeal: `CRITICAL` is hotter and lighter than it was (the old `#e36b76` is almost exactly the new chrome colour, so "on fire" would have read as "background"), and `PRESSURE_CRITICAL` likewise — the old ramp topped out at `#ab4a52`, which is the burgundy itself. Colours picked against the navy live on as named constants (`TRACK_BG`, `ROW_LINE`, `MAP_*`) rather than hex literals in widgets, so the next palette change is one file.

`theme.PARTY_PALETTE` colours parties and **never fills a map region**; the four-step `PRESSURE_*` ramp (`theme.pressure_color` / `pressure_word`) fills map regions and **never colours a party**. The two sets are disjoint on purpose — it is what lets a glance at the map read as "how much trouble" rather than "who won here". Territory the state does not administer (`control == "separatist"`) is drawn as a diagonal hatch over `OUTSIDE_ADMIN` grey and gets **no** pressure colour, so control status and pressure stay distinguishable; `limited` and `autonomous` regions *are* administered and keep their real pressure fill. The map legend names all five states in words, and `panel_right._pressure_label` delegates to `theme.pressure_word` so the legend, the fill and the readout can't disagree.

Map labels are drawn through `_halo_text` (a `QPainterPath` stroked in `theme.BG` under the fill) — without it, labels vanished into fills and into each other. Region names sit at the polygon's own **area centroid** (`_centroid`), not a hand-placed anchor; `REGION_LABEL_ANCHORS` is retained for reference only. City labels are offset to the right of their dot with a gap and are hidden unless the region is hovered or selected — the capital is always shown.

### The map

The dashboard is deliberately an **Ardenia map**, not a continent board. `ui/widgets_ardenia_map.py` draws the hand-authored original silhouette and six clickable regional polygons from `ui/ardenia_map_geometry.py`: northern mountains, the Kesla corridor, cities, strategic road/rail/pipeline routes, the coast, and Vetrenka's internal ceasefire line. `content/lore/ardenia_map_bible.md` fixes the spatial canon and adjacency; `geography.py` retains the stable regional and city ids. A selected region feeds the dashboard briefing; the wider world remains real in `GameState.world`, the relations list, dispatches and the Diplomacy page. The old procedural continent code is retained as an unused foundation for a later foreign-intelligence view, but it is not the player's main map.

### Regional simulation

`GameState.regions` owns Ardenia's live subnational state as `RegionState` objects (`models/region.py`): unemployment, state reach, political pressure, control and a stable defining-issue id. The authored starting profiles and structural gaps live in `content/regions.py`; names and geographic prose remain in `content/lore/geography.py`, so there is no second lore source. `engine/regions.py: simulate_regions` deterministically translates the national economy, bureaucratic capacity and stability into distinct monthly local outcomes. Control does not flip passively: sovereignty changes such as Vetrenka's status require explicit mechanics. Population-weighted regional pressure contributes modestly to the shared unrest signal. The map tints regions by live pressure, the selected-region panel explains all three measurements, and the Briefing ranks the most pressured areas. Countries without authored regional data keep an empty dict and remain fully buildable.

Regional programmes make the map operational. `content/regions.py: REGIONAL_PROGRAMS` defines the five authored instruments, their political-capital price, monthly treasury commitment, duration, portfolio, effects, party response and geographic fit. `GameState.regional_programs` persists active `RegionalProgram` commitments; `engine/regions.py` applies one month of delivery after the ordinary local drift, scaled by the responsible minister and bureaucratic capacity, and removes a programme on completion. Only one programme can run in a region at once. Separatist-controlled territory is inaccessible; an explicit Vetrenka settlement or reconquest changes that gate. The input-free action is `player_ops.op_start_regional_program`; both the selected-region controls and the CLI's appended `Regional` category call it. Programmes already underway continue under the actual cabinet after an election, but an opposition player cannot launch one.

Each `RegionState` also carries normalized `party_support` and a `support_anchor`. Authored 1993 baselines make Vashtera and Kelvet Liberal Democrat starts, Anera National Conservative country, Zavost competitive, and Sela agrarian-sensitive. `engine/regions.update_party_support` reconciles national polling changes into every region without erasing this local character, then judges the sitting party by local unemployment, pressure, state reach and household confidence. Programme beneficiaries gain support where delivery occurs. `player_ops.op_campaign_region` lets either government or opposition spend 7 PC to move one reachable electorate, with a three-month per-region cooldown and a smaller national polling echo. `engine/elections.compute_turnout` aggregates each region's population weight, local support, party enthusiasm and `electoral_access`; separatist Vetrenka contributes no ballot, limited Anera contributes fewer, and explicit control changes alter access. `ElectionResult` persists regional vote shares, turnout and access, and the election log prints every regional winner. Countries without regional data retain the exact national turnout path.

### Persistence

`engine/persistence.py` maps `GameState` ↔ JSON **by hand**, versioned and tolerant (missing fields → model defaults). **Any new field on `GameState` or a nested model must be added to `serialize_state`/`deserialize_state` or it silently won't round-trip.** GUI autosaves each turn to the `autosave` slot in `saves/`.

## Gotchas

- Never name a `QDialog` subclass attribute `self.event` — it shadows Qt's internal `event()` method and breaks event dispatch (use `self._event`).
- **A long non-wrapping `QLabel` sets the window's minimum size.** Qt propagates a label's full text width up through every parent, so a status line or alert whose text changes at runtime makes the *window* grow on its own — it reads as the UI "zooming in", and with a dock open it can exceed the screen. Use `widgets_common.ElidedLabel` for any single-line text that varies, and give panels whose content grows (right panel, scroll columns) an explicit `setMinimumWidth/Height` — an explicit minimum overrides `minimumSizeHint`, so content scrolls instead of resizing the window. Same reason `AlertStrip` reserves a fixed-height band rather than growing with the alert count.
- Some `smoke_test.py` Section B/H tests drive the CLI menu with hardcoded positional input sequences — a menu reorder can silently exercise the wrong action rather than fail loudly. Known debt.
- In `smoke_test.py`, Section G8 reassigns the name `bill` from the helper function to a Law object — sections after G must fetch bills via `next(b for b in bill_catalog() if b.id == ...)`, never `bill(...)`. Has bitten twice (K6, O1).
- `content/countries/*.json` faction ids are still referenced by **bills** (`content/bills.py`) loyalty deltas; unknown ids are skipped safely, so those degrade gracefully rather than crashing. **Events no longer use literal faction ids at all** — they use roles (see "Country-neutral content"). If you add a delta to an event, use a `ROLE_*` key, and remember two ids that map to the same role would silently collide as dict keys.
